Auth, limits and logs in front of any MCP server.

An MCP server usually ships with one static token pasted into every client config, or with no auth at all because it sits on a private network. Both fail the moment the server is worth using: the token ends up in a dotfile on five laptops and cannot be revoked per person, and “on the private network” is one misrouted Service away from the internet.

Point the client at the gateway instead. It terminates the login or verifies a bearer key, checks that the caller belongs to the gateway’s tenant, enforces a per-caller budget, and records every call with its payload.

Live deployment: mcp-gateway.giomartins.dev. The manual is served by the same app, signed out, so it can never describe a different version.

Three decisions, in this order

The gateway does not care what your MCP server does. It decides who reaches it, how often, and leaves a record of what happened.

01

Point it at your server

Give the gateway a slug and the upstream MCP URL. The upstream stays unreachable from outside; the gateway is the only door.

02

Choose who gets in

No auth for a private network, a bearer key for machines, or SSO for people — GitHub, Google, Microsoft, Discord, any OIDC provider, or the gateway’s own identity provider when you have none. Each gateway decides for itself, and a single gateway can accept keys and logins at once.

03

Paste the endpoint

/g/<slug>/mcp goes into the client. For OAuth, the client discovers the rest from the 401 challenge on its own. Every tenant starts with one gateway already there: the deployment’s own read-only console.

Client config

// ~/.config/mcp/config.json
{
  "mcpServers": {
    "rancher": {
      "url": "https://gateway.example.com/g/rancher/mcp"
    },
    "postgres": {
      "url": "https://gateway.example.com/g/postgres/mcp",
      "headers": { "Authorization": "Bearer omg_…" }
    }
  }
}

The refusal, before the tool runs

# no credential on an OAuth gateway
$ curl -sS https://gateway.example.com/g/rancher/mcp \
    -H 'Accept: application/json'
401  WWW-Authenticate: Bearer resource_metadata=…

# a key that belongs to another tenant
$ curl -sS …/g/postgres/mcp -H "Authorization: Bearer omg_…"
403  {"error":"forbidden","message":"'api-key:key_…' is not allowed…"}

# one caller over its ceiling
429  Retry-After: 60

What it does, and what it refuses

Fail closed is the default: an OAuth gateway with no credentials answers 503, never as an open proxy. Everything below is visible in the panel, because a control you cannot audit is a control you cannot defend.

403

Identity you already have

GitHub, Google, Microsoft, Discord or any OIDC provider — or the gateway’s own provider, so a self-hosted install with no IdP still gets SSO. Who may call is decided by the tenant that owns the gateway, read fresh on every request.

{ }

One endpoint per MCP server

Clients point at /g/<slug>/mcp. The gateway terminates OAuth or verifies a bearer key, then calls the real server over the private network with an upstream credential the caller never holds.

429

Per-caller budgets

Requests per minute per subject, counting JSON-RPC calls only — handshakes and notifications are free — plus an optional monthly quota. Redis-backed, so the limit is the same on every replica.

log

Every call is a row

Subject, outcome, status, latency, IP, tool name and a capped payload trace with the request and the response, appended to an event log that backs both the traffic table and the audit trail.

yaml

Panel and file are the same

Export the tenant to YAML, edit it, apply it back. Both paths reach one command handler, so they cannot disagree — and the panel shows the diff before an apply.

›_

A console you can ask

Every tenant ships with a gateway to this deployment’s own read-only MCP. Point an agent at /g/console/mcp and ask what broke, or what the audit log says.

Run it yourself

One compose file, Postgres included. The first account to register becomes the deployment’s admin, and every tenant starts with a working read-only console gateway, so there is something to call before you wire anything up.

Bring it up

# Postgres + the app, listening on :8000
git clone https://github.com/giomartinsdev/OpenMCPGateway
cd OpenMCPGateway
docker compose up -d --build

# the panel and the manual are the same app
open http://localhost:8000

Call a gateway

# initialize, then tools/list — the transport is stateful
curl -sS http://localhost:8000/g/console/mcp \
  -H "Authorization: Bearer omg_…" \
  -H 'Accept: application/json, text/event-stream' \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize",
       "params":{"protocolVersion":"2025-06-18",
                 "capabilities":{},
                 "clientInfo":{"name":"curl","version":"1"}}}'

# a 200 here is an SSE frame, not a JSON document
event: message
data: {"jsonrpc":"2.0","id":1,"result":{…}}
